# 9. UX 재구성 기획 (구조·컨셉 재설계)

> 목적: "예쁘게"가 아니라 **사용자가 쓰기 좋은 구조**로 앱을 다시 짠다. 정보구조(IA)·화면 흐름·네비게이션.
> 상태: **기획 중 (같이 결정)**. 작성 2026-08-03.

---

## 9.1 이 앱은 무엇을 위한 앱인가 (사용자 목표 / Jobs to be done)

노포·야장(서울 숨은 맛집)을 찾는 사용자의 실제 목적:

| # | 목표(Job) | 지금 충족도 |
|---|-----------|-------------|
| J1 | **발견** — 숨은 명가를 둘러보며 영감 얻기 (앱의 정체성 "숨은 맛") | ⚠️ 약함 — 평점순 그리드 하나, 큐레이션 없음 |
| J2 | **근처 탐색** — 내 위치/특정 동네의 좋은 집 | ⚠️ 묻힘 — 위치 버튼+거리순, 지도는 토글 뒤 |
| J3 | **목적 검색** — 상황·메뉴(회식/혼밥/국밥/해장/데이트)로 찾기 | ⚠️ AI만 함(버튼 뒤), 필터는 속성 기반 |
| J4 | **저장·관리** — 내 리스트, 방문 기록, 공유 | △ 흩어짐 — 즐겨찾기·방문이 필터로만 |
| J5 | **신뢰 판단** — 평점·리뷰·영업 여부 | ✅ 있음 |

**진단**: 현재는 본질적으로 **"평점순 그리드 + 탭 전환"**. 강력한 필터가 있지만, "발견"이라는 앱의 핵심 가치를 화면 구조가 못 살림. 열면 490개가 평점순으로 쭉 나올 뿐, 둘러보는 재미·안내·맥락이 없음.

## 9.2 목표 구조 (제안)

핵심 전환: **"필터링하는 그리드"** → **"둘러보고 발견하는 앱"**.

### A. 네비게이션 — 목적별 공간 분리 (하단 탭)
현재 한 화면에 다 쑤셔넣은 걸, 4개 공간으로:

| 탭 | 담당 Job | 내용 |
|----|----------|------|
| 🏠 **홈(발견)** | J1, J3 | 큐레이션 발견 피드 (아래 B) |
| 🗺 **지도** | J2 | 지도 우선 위치 탐색 (다크 지도 + 하단 리스트) |
| ✨ **AI 추천** | J3 | 대화형 추천 (지금은 버튼 뒤 → 일급 진입점으로) |
| ♡ **내 리스트** | J4 | 즐겨찾기 + 방문 기록 + 내 리뷰 통합 |

> 데스크톱은 하단 탭 대신 상단/사이드 내비로 동일 구조.

### B. 홈 = 큐레이션 발견 피드 (가로 레일)
평점순 한 덩어리 대신, **맥락별 가로 스크롤 레일**로:
1. **오늘의 발견** (히어로, 이미 있음) — 매일 바뀌는 고평점 픽
2. **내 근처** (위치 ON 시) — 반경 내 가까운 순
3. **지금 영업중** — 영업 데이터 기반
4. **큐레이션 컬렉션** — 규칙 생성(수작업 없이):
   - "국밥·곰탕 명가" (메뉴 매칭 + 고평점)
   - "한잔하기 좋은 야장"
   - "혼밥 좋은 곳" (국밥·백반·면 + 고평점)
   - "리뷰 많은 집" (커뮤니티 리뷰순)
5. **지역별로 둘러보기** — 구 칩 → 그 동네 모음
6. **전체 보기** → 기존 필터·정렬 그리드(검색 결과 화면으로 유지)

> **큐레이션 실현성**: 전부 `data.json`으로 규칙 생성 가능(메뉴 키워드·평점·영업·리뷰수·거리). AI 의도 매핑에서 이미 검증한 방식. 편집자 불필요.

### C. 노포/야장 축
브랜드 정체성이라 **상단 토글로 유지**. 홈 레일은 선택된 카테고리 안에서 구성(또는 "전체" 포함 검토).

### D. 저장·개인화
흩어진 즐겨찾기·방문·리뷰를 **"내 리스트" 탭 하나**로. 공유(=share)도 여기서.

## 9.3 단계적 실행 (점진 — 각 단계 실화면 검증)

기존 기능은 유지하며 구조만 얹는다. 위험 최소화 순서:

- ✅ **Phase 1 — 홈 발견 피드** (완료 2026-08-03): 랜딩을 평점 그리드 → 큐레이션 레일로. 기존 그리드는 검색/필터 시 폴백. `utils/collections.js`(규칙 생성) + `RestaurantRail.jsx`.
- ✅ **Phase 2 — 하단 탭 내비** (완료 2026-08-03): 발견/지도/AI/내 리스트 4탭. `BottomNav.jsx`. 헤더 뷰토글·AI 버튼을 탭으로 승격.
- ✅ **Phase 3 — 내 리스트 통합 공간** (완료 2026-08-03): 즐겨찾기·가본 곳·내 평가 세그먼트 + 공유. `MyListSpace.jsx`.
- ✅ **Phase 4 — 지도 일급화** (완료 2026-08-03): 지도 탭 하단 시트(접이식) — 목록·지도 동시, 행 탭 시 flyTo + 상세. `MapView.jsx`.

각 단계 후 스크린샷 검증 + 피드백 → 다음.

**결과**: "평점순 그리드 + 탭 전환" → "둘러보고 발견하는 앱"으로 전환 완료. 후속 정리(헤더 슬림화 등)는 9.5 참고.

## 9.4 같이 정할 핵심 결정

1. **네비게이션 모델**: 하단 탭 4개(홈/지도/AI/내 리스트)로 가는가? (모바일 앱다움 ↑, 구현 큼)
2. **홈 레일 구성**: 위 B의 레일 목록에서 뺄/더할 것? (예: "데이트" 컬렉션, "성시경 추천" 같은 밈은 데이터 없어 불가)
3. **우선순위**: Phase 1(발견 홈)부터 vs 다른 순서?
4. **노포/야장**: 홈에서 카테고리별 분리 유지 vs "전체 발견" 통합?

→ 결정: 하단 탭 4개 / 홈 레일 초안대로 / Phase 1부터 / 노포·야장 상단 토글 유지. Phase 1~4 모두 반영 완료.
