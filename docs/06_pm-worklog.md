   - 실행: `node src/businessHours.test.js` → 통과.

### 크롤러 장애 진단 & 복구 (버그 2개)

크롤러를 재실행하는 과정에서 **연쇄된 버그 2개**를 발견·수정했다.

**버그 ① 드라이버 초기화 무한 대기**
- **증상**: 로컬 크롤 실행 시 23시간 동안 0% CPU로 멈춤. DB·로그에 아무 기록 없음.
- **근본 원인**: `ChromeDriverManager().install()`가 `storage.googleapis.com`에서
  드라이버를 받으려다 **네트워크 타임아웃에 무한 대기**(타임아웃 미설정).
- **수정** — `crawling/kakaomap.py` `init_driver`:
  `CHROMEDRIVER_PATH` 환경변수가 있으면 그 드라이버를 직접 사용, 없으면 기존 자동 해석.
  → 로컬은 캐시 드라이버로 네트워크 회피, CI(리눅스)는 영향 없음.

**버그 ② CSV 저장 크래시로 DB 저장이 매번 스킵됨 (조용한 데이터 유실)**
- **증상**: ①을 고친 뒤 크롤이 끝까지 돌았는데도 영업시간이 2건 그대로. DB에 아무것도 안 들어감.
- **근본 원인**: 영업시간 기능 추가 시 행(dict)에 `영업시간/휴무일/결제수단` 키가 생겼는데,
  `save_to_csv`의 `fieldnames`엔 빠져 있어 `csv.DictWriter`가 매 지역 예외 발생.
  루프상 **CSV 저장이 DB 저장보다 먼저** 호출돼서, 예외→`except`로 점프→`save_to_db` 미실행.
  모든 지역에서 DB 저장이 조용히 건너뛰어졌고, 루프 밖 마지막 CSV 저장에서 예외가 잡히지 않아 크래시.
- **수정** — `save_to_csv`의 DictWriter에 `extrasaction='ignore'` (CSV엔 영업시간 안 쓰므로 추가 키 무시).
- **검증**: 강남구 단일 스모크 → "✅ 저장 완료" 출력, `with_hours` 2→13, 자정 넘김·브레이크타임 정상.
- **실행 방법(로컬)**:
  ```bash
  CHROMEDRIVER_PATH=~/.wdm/drivers/chromedriver/mac64/<버전>/chromedriver-mac-arm64/chromedriver \
    venv/bin/python -u crawling/kakaomap.py
  ```
  ※ 캐시 드라이버 버전은 설치된 Chrome의 **major 버전과 일치**해야 함
  (`Google Chrome --version`으로 확인).
- **현재**: 전체 재크롤 진행 중(25개 구 × 2 카테고리, 1~2시간). 완료 후 영업시간/좌표 보강 예정.

## 6.5 후속 과제 처리 (2차 세션)

### ① 좌표 보강 (geocode.py 개선)
- 재크롤로 신규 324곳이 들어오며 좌표 미해결이 455곳까지 늘었고, 1차 지오코딩으로 244곳 해결(잔여 211).
- 잔여 211곳은 전부 `"...로 631-3 1층 102호"`처럼 **건물명/층/호 상세주소**라 Nominatim이 못 풂.
- **수정** — `geocode.py`에 `road_level()` 추가: 도로명+건물번호까지만 남기고 절단하는 3차 쿼리 폴백.
  `"고산자로36길"`처럼 도로명에 숫자가 박힌 복합 도로명은 그리디 매칭으로 처리.
- 잔여분 재지오코딩으로 좌표 커버리지 추가 확보 (결과는 커밋 메시지 참고).

### ② 평점 5.0 쏠림 — **데이터 부족으로 보류 (수정 안 함)**
- 신규 야장에 평점 5.0이 몰려 평점순 상단을 차지하는 현상. 단, 5.0은 43/1029곳으로 분포 자체는 완만.
- **근본 한계**: 크롤러가 **리뷰 수를 수집하지 않음** → 리뷰 5개짜리 5.0과 500개짜리 4.5를 구분할 근거가 없음.
  리뷰 수 없이 정렬을 손대는 건 근거 없는 추측이라 **하지 않음**.
- **제대로 고치려면**: `kakaomap.py`가 리뷰 수도 수집 → 베이지안 평균(가중 평점)으로 정렬.
  크롤러 수정 + 전체 재크롤이 필요한 별도 작업이라 백로그로 분리.

### ③ backend FastAPI 서버 제거
- 프론트는 `/api/chat`(Vercel)·`/data.json`(static)만 호출. FastAPI(`/api/restaurants`,`/api/stats`)는
  코드 어디서도 참조 안 됨 → 죽은 코드 확인.
- **제거**: `main.py`, `Procfile`, `railway.toml`, `requirements.txt`, `.env.example`, `server.log`.
- **유지**: `restaurants.db`(데이터), `init_db.py`/`migrate_hours.py`(크롤러·CI가 사용).

## 6.6 UX/UI 개선 (3차 세션)

기획자 관점으로 실제 화면(데스크톱/모바일 스크린샷)을 점검해 개선점을 도출하고 우선순위대로 적용.
모두 `App.jsx` + `index.css` 변경, build 통과·신규 lint 에러 0, 라이브 배포 완료.

### 적용 (P0 — 방향성·기본기)
- **결과 수 상시 표시** — 기존엔 필터를 걸어야만 "N개 결과"가 보여 첫 진입 시 데이터 규모를 알 수 없었음.
  이제 기본 화면에도 항상 표시(천단위 포맷).
- **검색 인라인 ✕ 클리어 버튼** — 검색어를 한 번에 지우는 버튼 추가.
- **필터별 빈 상태 + 초기화 버튼** — "영업중 0건"에도 "지역을 못 찾음"이라 뜨던 오해 해소.
  검색어/영업중/안가본곳/반경별 맞춤 문구 + `필터 초기화` 버튼.

### 적용 (P1 — 접근성·인터랙션 정합성)
- **거리순 정렬 가드** — 위치 OFF에서 거리순을 골라도 아무 일 없던 함정 → 선택 시 위치 요청 자동 트리거.
- **모달 접근성** — `role="dialog"` / `aria-modal` / `aria-labelledby`.
- **aria-label** — 지역/정렬/반경 select, 랜덤 FAB.

### 적용 (P2 — 폴리시)
- **모바일 타이틀 줄바꿈 방지** — "노포지도"가 2줄로 깨지던 것 수정.
- **랜덤 FAB가 마지막 카드 가림 방지** — 그리드 하단 여백 확보.

### 검증 방식
- vite dev 구동 → Selenium(cached 149 driver)으로 데스크톱(1440)·모바일(390)·빈상태 스크린샷 전후 비교.

## 6.7 메인 레이아웃 개편 — 매거진 그리드 (확정, 구현 대기)

평점순으로 1,029곳이 균일하게 늘어선 단조로운 카드 리스트를 개선. 후보 3안(큐레이션 피드 / 지도 우선 / 매거진 그리드) 중 **매거진 그리드**로 확정 (최소 변경으로 단조로움 완화, 사진 데이터 불필요).

**제약**: 데이터에 사진 없음(크롤러 미수집) → 이미지 그리드류는 불가. 정보(메뉴/평점/지역)로 큰 카드를 채움.

### 스펙
1. **featured "오늘의 발견" 큰 카드** (그리드 상단)
   - 선정: 현재 카테고리(노포/야장) 안에서 **날짜 시드 결정적 픽**(오늘 하루 고정, 매일 변경). `Math.random` 아닌 날짜 해시 → 재렌더 안정 + purity 룰 회피.
   - 내용: 이모지+상호명(크게), 지역, ⭐평점, 주소, 대표메뉴 태그, 영업중 배지, (위치 ON 시)거리. `🎲 다른 곳` 리셔플 버튼(랜덤 로직 재활용).
   - 노출 조건: **홈 상태에서만** — 검색·필터·지도뷰·공유모드·즐겨찾기보기일 땐 숨김(의도 탐색 시 순수 결과).
2. **섹션 헤더**: 그리드 위 `── 평점순 · N곳 ──`(정렬기준+개수 반영).
3. 기존 카드 그리드는 그대로 유지.

### 비용/타이밍
- `FeaturedCard` 컴포넌트(~40줄) + 날짜픽 useMemo + 섹션헤더 + 조건부 렌더 + CSS. 새 데이터 불필요.
- **App.jsx 헤비 변경** → 미커밋 보류 중인 베이지안 정렬(App.jsx)을 재크롤 후 확정·배포한 **다음에** 착수(충돌 방지).

## 6.8 듀얼 톤 아트 디렉션 (노포=빈티지 / 야장=네온)

"기능엔 충실하나 개성 없는 다크 템플릿" 피드백 → **카테고리별 아트 디렉션**으로 격상. 사진 데이터가 없어 타이포·색·질감 중심. 기존 `.yajang-theme` 전환 구조 재활용(CSS 변수 값만 교체 → 전 컴포넌트 전파).

### 방향
- **노포**: 따뜻한 브라운(`#1C1510`) + 앰버 골드(`#C8964A`), Noto Serif KR 제목, 종이 그레인·골드 강조선 → 세월·정겨움
- **야장**: 미드나잇 퍼플(`#0D0A1A`) + 네온 민트(`#3DFFC8`), Pretendard 800 제목, 비네트·네온 라인·민트 글로우 → 밤거리
- 제네릭 로즈(`#f43f5e`) 완전 폐기(하드코딩 포함). 시맨틱 색(영업 초록/별점 골드/마감 빨강) 유지.

### 구현 (5단계, 전부 배포)
1. **토큰 교체** — `:root`=노포, `.yajang-theme`=야장 전면 오버라이드(배경·텍스트·border·glass·shadow).
2. **타이포** — Pretendard(본문, npm dynamic-subset ~200KB) + Noto Serif KR(제목, Google Fonts), `--font-display` 변수. Inter 제거.
3. **질감** — 노포 SVG feTurbulence 그레인(data-URI)·앰버 블롭·골드선 / 야장 비네트·네온선·inset glow. 전부 CSS, `pointer-events:none`·콘텐츠 뒤 z-index.
4. **이모지 프레임** — 카드/featured/모달 이모지를 앰버/민트 원형 프레임으로(aria-hidden).
5. **모션** — 테마 전환 배경 blending, 톤별 hover 타이밍(노포 300ms/야장 200ms), `prefers-reduced-motion` 존중.

### 검증
- 접근성 대비 AA+ (앰버 5.1:1 / 민트 7.2:1). 인터랙션 회귀 없음(오버레이가 클릭·스크롤 비방해). lint 0, build 통과. 노포·야장 데스크톱+모바일 스크린샷 확인.
- 관련 파일: `index.css`(토큰·질감·모션), `index.html`(폰트), `main.jsx`(Pretendard), `components/RestaurantCard.jsx`(이모지 span).

## 6.9 AI 추천(챗봇) 모델 업그레이드 + 후보 선별 개선

"AI 추천 성능이 안 좋다" 피드백 → 라이브 진단으로 **원인은 모델이 아니라 후보 선별 로직**임을 확인하고 수정.

### 진단
- 라이브 질문 테스트 결과, 모델 답변 품질·grounding·환각 방지는 양호.
- 결정적 버그: `findRelevant`가 지역을 `질문.includes('강남구')`로만 매칭 → 사용자가 "강남"으로 검색하면 매칭 실패 → 강남 식당 가점 누락 → 후보 20곳에서 탈락.
  - 실증: "강남 국밥집" 질문에 "정보 없음"이라 **오답**. 실제 데이터엔 강남구 국밥/탕류 8곳(하동관 곰탕 등) 존재.

### 수정 (`frontend/api/chat.js`)
1. **모델**: `gemini-2.5-flash` → `gemini-3.6-flash` (2026-07 GA). 파라미터 마이그레이션: `thinkingBudget`(3.x 폐기) → `thinkingLevel:'low'`.
2. **지역 유연 매칭** (`matchRegion`): 정식 이름("강남구") → 구 접미사 뗀 어간("강남", 2자+) → 동네 별칭("홍대"→마포구 등) 순. 항상 정식 구 이름 반환. matchRegion 단위테스트 8/8.
3. **후보 수** 20 → 40 (3.6 Flash 컨텍스트 여유).
4. **의도어 매핑** (`INTENTS`): 데이터에 없는 의도어(회식/혼밥/부모님/술/해장/깔끔)를 메뉴 키워드·카테고리·최소평점 가점으로 변환.

### 검증
- 라이브 재테스트: "강남 국밥"→하동관 곰탕 등 정상, "부모님 깔끔한"→백숙/을밀대, "홍대 술 한잔"→홍대 야장. 전부 개선 확인.
- lint 0, build 통과. 실데이터로 findRelevant 스코어링 검증.

## 6.10 폐업 sweep 오탐 대량 은닉 수정

README 갱신 중 식당 수가 1,110→793으로 급감한 걸 발견 → 진단 결과 폐업 소프트 정리(6.5 ③)의 **심각한 오탐**이었음.

### 진단
- 숨겨진(active=0) 식당 **357개(전체의 31%)**, 그중 335개가 missed_crawls=4. ⭐5.0 식당 다수 포함 → 폐업이라기엔 부자연.
- **근본 버그**: `run_sweep`이 `category IN (...) AND region IN (...)` **카테시안**으로 동작. 전체 주간 크롤은 25구×2카테고리가 모두 scope에 들어가므로 **DB 전체가 대상** → "0건 지역 제외" 가드가 무력화. 카카오 검색이 회차마다 상위 결과를 덜 반환(정상 변동)하면 실존 식당이 미발견 처리 → 3회 누적 → 대량 은닉.

### 수정 (`crawling/kakaomap.py` `run_sweep`)
1. **쌍(category, region) 단위 처리** — 카테시안 제거, 실제 크롤한 쌍만 정확히. 0-가드 실효화.
2. **건강도 가드** (`HEALTHY_RATIO=0.5`) — 어떤 쌍의 크롤 결과가 기존 active 행의 절반(최소 3건) 미만이면 '부분 크롤'로 보고 미발견 처리 스킵. 카카오 랭킹 변동에 강건.
3. 발견 행은 건강도와 무관하게 항상 복구.

### 복구·검증
- 잘못 숨겨진 357곳 클린 슬레이트 복구(active=1, missed_crawls=0) → **793→1,150곳**, data.json 재생성.
- 시뮬레이션 4/4 통과: 건강한 크롤(미발견 카운트)·부분 크롤(가드 스킵)·3회 연속 미발견(정상 폐업 감지)·0건(스킵).

### 남은 후속 (선택)
- 크롤러가 왜 회차마다 결과 수가 출렁이는지(카카오 랭킹/차단/타임아웃) 근본 진단 — 가드로 증상은 방어됨.
